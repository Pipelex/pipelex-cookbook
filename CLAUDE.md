# pipelex-cookbook

The cookbook holds Pipelex's example methods as packages runnable by address, each with a generated page. `docs/README.md` explains how it works, and `docs/adding-a-method.md` and `docs/adding-a-recipe.md` how to add a method or a recipe.

- **Method pages are generated.** `methods/<name>/README.md` is written by `make render` from the package (`METHODS.toml`, `inputs.json`, `contract.json`, `output.json`), `cookbook.toml` and `templates/`, and so are the page's snippet files under `tests/snippets/<name>/` and the two lists of the root `README.md`: the methods, between the `BEGIN methods` and `END methods` markers, and the library's methods, between `BEGIN library` and `END library`, from `library.json`. Never edit a page, anything under `tests/snippets/<name>/` or those regions by hand: change its sources and run `make render`. To list a newer library release, move `[library].tag` in `cookbook.toml`, then run `make refresh-library` and `make render`. `make check-render` fails on any difference.
- **When a bundle changes**, run `make refresh` (needs `PIPELEX_API_KEY`): it rewrites every `contract.json`, renders, then regenerates the types under every `generated/` tree, the page snippets' included, whose sidecars name the package's `.mthds` files. `make check-codegen-live` fails on a snippet's types that no longer come from its package's files. Every other command fails first, when a main pipe no longer returns what its `contract.json` records.
- **Every sample input has a source-and-licence record** under `[methods.<name>.samples.<input>]` in `cookbook.toml`: a real input is an openly licensed document copied under `assets/<name>/` with its source, date, licence and credit, and a made-up one says `synthetic = true`. Never invent a source or a licence to fill a record; `make check-render` fails on an input without one.
- **A page's "What you get" comes from `output.json`, the output snapshot**, taken by `make snapshot METHOD=<name>` from one run on production, with the files the output holds under `methods/<name>/output/`. That run spends inference credit: never start it, or any other production run, without the approval of whoever pays for it. `make check-render` fails on a missing snapshot, one out of step with its contract, sample or files, and a document sample without its preview, and only warns when the bundles changed since.
- **Keyed checks run by hand.** CI holds no API key, so `make check-hosted` (`check-methods`, `check-addresses` and `check-codegen-live`) is run before each pull request that touches a method, a page, a recipe or the tutorial, whose bundles `check-methods` validates too. None of them spends inference.
- **`make check-smoke` spends credit, unlike every other check.** It runs every method once on production on its sample (needs `PIPELEX_API_KEY`) and fails when one does not validate, does not complete or returns output that is not of its contract's shape; `METHOD=<name>` narrows it and `ROUTE=address` runs each page's address at its tag. Its tests carry the `smoke` marker, which pytest deselects everywhere else, so `make test`, `make agent-test`, `make check-hosted` and CI never run it; start it only when a run is agreed.
- **Every manifest carries the cookbook's version** from `pyproject.toml` (`make check-lockstep`).
- **A recipe's `generated/` tree is written by codegen.** `models.py` and `codegen.lock` come from the address in the tree's `sources.json`: never edit them, and never let a formatter touch them. Change the address in `sources.json` and the recipe's code together, then run `make refresh` (needs `PIPELEX_API_KEY`): `make check-recipes` fails when the two disagree, `make check-codegen` when a generated file was edited, and `make check-codegen-live` when the lock is not from what the address resolves to. `docs/adding-a-recipe.md` says how to add a recipe.
